# Optimizer — параметрическая оптимизация ТВД

Инструмент использует **существующую** модель проекта:

* `../Turbinis-Cycle/Turbinis-Cycle.ipynb` — цикл (через `cycle_link.py`);
* `../Turbinis-Calc/Main_Turbinis_Calc_Book.ipynb` — поступенчатый расчёт (п. 1–153).

Новая физическая модель не создавалась. `optimizer_core.py` исполняет те же код-ячейки
блокнота, что и рабочий расчёт, и добавляет пересчёт цикла, валидацию, поиск и экспорт.

> **Плоскость мощности (2026-11-10).** Пользователь подтвердил: N = 110 кВт — мощность
> на **входе редуктора** (до `η_р`). Активные `optimizer_core.cycle_point`,
> `optimize_extended.eval_candidate`, `turbine_engine.baseline` и
> `turbine_engine.performance` используют эту плоскость. Исторические scan-скрипты и
> старые `results/` могут относиться к прежней post-reducer трактовке; не смешивайте их
> с новыми anchor без пересчёта. Подробности — `../docs/comparisons/Источники_и_методики.md` §6.

## Запуск

Из папки `Optimizer` в контейнере `jupyter`:

```bash
jupyter nbconvert --to notebook --execute --inplace Turbinis-Parametric-Optimization.ipynb
python optimize_initial_conditions.py --mode 1 --quick
```

В ноутбуке режим задаётся в `CONFIG["mode"]`:

* `A` — π*к = 11, N = 110 кВт;
* `B` — π*к — переменная, цикл пересчитывается;
* `C` — N — переменная (масштабирование).

`QUICK=True` уменьшает бюджеты DE и локальной доводки.

## Что проверяется

Жёсткие (`hard`): z = 3; α1 ≥ 11°; α2 70…90° (1-я и промежуточные) и 80…90° (последняя);
π ступени 1,8…2,4; σ_р ≤ σ_л; u_т ≤ 400 м/с; l_с1 ≥ 14 мм; p2z = p_т; N = требуемая;
невязки неразрывности и энергии; при полном расчёте — γ ≤ 25°, ρ корня ≥ 0,05, λ_c1 ≤ 1,05.

Проектные (`project`): D1 ≤ D2 ≤ D3 = 1; l_т/D_т ≤ 1/3; длины лопаток не убывают.

Цели (`target`): l_с1 ≥ 20 мм; η*т ≥ 0,90.

## Исправленная ошибка

В ячейке 16 блокнота внешний итератор расхода `G` (метод секущих) при повторных вызовах
накапливал умножение `G_c1`, `G_л_ост`, `A_т0` на `k = G/G_в`. При N = 110 кВт это сходилось,
при масштабировании N — `A_т0` уходил в минус и `math.sqrt` давал `domain error`.
Исправление в `optimizer_core._NEW_G`: каждый вызов `N_of(G)` начинается с одного и того же
базового состояния, `G` ограничен положительным диапазоном. Формулы не изменены.
Начиная с извлечения `turbine_engine/baseline.py` этот же patched-код ячейки 16
исполняется модулем на пути `_evaluate(stage_core=True)`; pandas-таблицы и
`display` там не строятся. `_evaluate(stage_core=False)` по-прежнему исполняет
patched-ячейку 16 целиком как независимый эталон.

> **Статус:** оцифровка пользователя получена. Рис. 19 — PCHIP; рис. 18:
> сплошная предварительная, пунктир `frame_clipped` (до ρ≈0.646). Проверки
> `u/c0`/`u/c1` — `NOT_CHECKED`. Пилот `optimize_extended.py` выполнен;
> полный 10-seed прогон — отдельно. См. `Turbinis-Calc/PENDING.md`.

| 0.81 | 1.036 | 13.54 | 0.1521 | 0.549 | нет |

## Новый путь: диаметры из A и l/D

`Turbinis-Calc/sizing.py` и `optimizer_core.evaluate_sizing` реализуют последовательность
`A = Gv/ca` → `D_ср = √(A/(πλ))` → `l = λD_ср` → `D_вт = D_ср − l`.
`D_вт = const` подбирается λ_i; первая итерация даёт `D_вт = 62.48 / 62.43 / 62.47 мм`
(разброс 0.054 мм), `l/D = 0.169 / 0.272 / 0.290`, `l_с1 = 13.93 мм`,
`η*т = 0.9117`. Условие `u/c0 ≈ (u/c0)опт` пока не выполнено
(0.430/0.534/0.565 против 0.559/0.580/0.584) — это следующая итерация.
Старый расчёт по `D_ст` оставлен для сравнения; полная замена внешнего цикла
`N/G/A_т` — следующий шаг.

## Замыкание D_вт = const (последняя итерация)

`ступень_const_hub` в блокноте задаёт `l = (√(D_вт²+4A/π)−D_вт)/2`, `D = D_вт+l`;
`D_вт` одинаков на всех сечениях. Лучшая точка: `n = 84 000`, `D_вт = 65 мм`,
`π_веса = [0.75, 0.80, 1.0]`, `G` под `N = 110 кВт`:
`α2 = 73.0 / 74.6 / 81.2°`, `u/c0 = 0.506 / 0.581 / 0.582` (опт 0.531 / 0.569 / 0.576),
`l_с1 = 13.28 мм`, `σ_max = 314 МПа`.
Сетка `n × D_вт` показывает конфликт: `l_с1 ≥ 14` достигается при `D_вт ≈ 58`
(`l = 14.66`), но α2 падает до 48/49/63, а σ = 319; при `D_вт = 65` α2 в книге,
но `l_с1 = 13.28` и σ = 314. Одновременно α2 + l≥14 + σ≤300 не получается.

**Следующий шаг:** `Turbinis-Calc/ТЗ_расширенная_оптимизация_2026-11-08.md` —
многопараметрическая оптимизация `n, D_вт, w1, w2, α1, κ` с проверкой
существования допустимой области; `σ ≤ 300` и `l_с1 ≥ 14` не ослабляются.

## Аудит послаблений

В оптимизаторе (`optimizer_core.validate`) оставлены только книжные/физические границы:

* α2 1-й и промежуточных ступеней — **70…90°**, последней — **80…90°**;
  ослабление 1-й ступени — только явно через `cfg["limits"]["a2_lo_first"] = 20`;
* α1 средний и у корня — **≥ 11°**; поиск `α1` — 11…20/24°;
* σ_р — **≤ σ_л**; `σ_л` ограничено **120…300 МПа**: обычные лопатки 120…200, «особо напряжённые» ≤300; проектное 290 — специальная категория, требует материала/температуры (с. 57);
* **n < n_max** через `q_n = 0.995` (проектный запас 0.5 %, `DESIGN_ASSUMPTIONS`);
* `l_т/D_т` — поиск **1/9…1/3** (широкий, по таблице с. 58); книжная рекомендация последней ступени **0.25…1/3** проверяется отдельно (`recommendation`), но не сужает поиск;
* `κ` — **1.0…1.4/1.3**;
* `u_т ≤ 400` (450 при `lD < 1/6`), `π 1.8…2.4`, `γ ≤ 25°`, `ρ корня ≥ 0.05`
  (параметр `rho_root_min`), `λ_c1 ≤ 1.05`;
* длины — **0,1 %** на сходимость `G/A_т` (не физическое послабление);
* добавлены проверки **рис. 18/19**, `D_вт/D_нар`, `φ/ψ`, `δ`; `l/b_a` и `b_a_min`
  помечены **NOT_CHECKED** (есть в блокноте, яч. 22, но не в `validate`).

## Ограничения инструмента

* Бюджеты `QUICK` малы; для инженерной доводки увеличивайте `DE_MAXITER`, `DE_POPSIZE`, `LOCAL_STEPS`.
* Полная валидация (ρ корня, λ, γ, решётки) выполняется для финалистов; в DE используется ядро.
* DE стохастична; результаты зависят от `seed`, но проверяются независимо.
* Тёплый старт режима C — инженерная оценка по пределу `l_с1 ~ √N`; финальное решение считается моделью.
* Скрипт обратной оптимизации перебирает 6 точек в `--quick`; полный набор — 60 точек.
