# Optimizer — параметрическая оптимизация ТВД

Инструмент использует **существующую** модель проекта:

* `../Turbinis-Cycle/Turbinis-Cycle.ipynb` — цикл (через `cycle_link.py`);
* `../Turbinis-Calc/Main_Turbinis_Calc_Book.ipynb` — поступенчатый расчёт (п. 1–153).

Новая физическая модель не создавалась. `optimizer_core.py` исполняет те же код-ячейки
блокнота, что и рабочий расчёт, и добавляет пересчёт цикла, валидацию, поиск и экспорт.

## Файлы

| Файл | Назначение |
|---|---|
| `Turbinis-Parametric-Optimization.ipynb` | основной ноутбук (разделы 1–14) |
| `optimizer_core.py` | загрузка модели, цикл, валидация, DE/локальный поиск, Pareto, экспорт |
| `optimize_initial_conditions.py` | обратная оптимизация π*к / T*г / N |
| `scan_cycle_coefficients.py` | скан η_к и коэффициентов цикла при π*к = 11, N = 110 кВт |
| `results/` | CSV, Excel, JSON, PNG после прогона |

## Запуск

Из папки `Optimizer` в контейнере `jupyter`:

```bash
jupyter nbconvert --to notebook --execute --inplace Turbinis-Parametric-Optimization.ipynb
python optimize_initial_conditions.py --mode 1 --quick
```

В ноутбуке режим задаётся в `CONFIG["mode"]`:

* `A` — π*к = 11, N = 110 кВт;
* `B` — π*к — переменная, цикл пересчитывается;
* `C` — N — переменная (масштабирование).

`QUICK=True` уменьшает бюджеты DE и локальной доводки.

## Что проверяется

Жёсткие (`hard`): z = 3; α1 ≥ 11°; α2 70…90° (1-я и промежуточные) и 80…90° (последняя);
π ступени 1,8…2,4; σ_р ≤ σ_л; u_т ≤ 400 м/с; l_с1 ≥ 14 мм; p2z = p_т; N = требуемая;
невязки неразрывности и энергии; при полном расчёте — γ ≤ 25°, ρ корня ≥ 0,05, λ_c1 ≤ 1,05.

Проектные (`project`): D1 ≤ D2 ≤ D3 = 1; l_т/D_т ≤ 1/3; длины лопаток не убывают.

Цели (`target`): l_с1 ≥ 20 мм; η*т ≥ 0,90.

## Исправленная ошибка

В ячейке 16 блокнота внешний итератор расхода `G` (метод секущих) при повторных вызовах
накапливал умножение `G_c1`, `G_л_ост`, `A_т0` на `k = G/G_в`. При N = 110 кВт это сходилось,
при масштабировании N — `A_т0` уходил в минус и `math.sqrt` давал `domain error`.
Исправление в `optimizer_core._NEW_G`: каждый вызов `N_of(G)` начинается с одного и того же
базового состояния, `G` ограничен положительным диапазоном. Формулы не изменены.

## Фактические результаты прогона

### Исходный вариант (N = 110 кВт)

`l_с1 = 17.79 мм`, `α2 = 21.7 / 82.7 / 90.5°`, `π = 2.20 / 2.16 / 2.37`, `η*т = 0.9063`.
Совпадает с рабочим блокнотом. При жёстком α2 1-й ступени ≥ 70° и l_с1 ≥ 20 мм — **недопустим**.

### Режим A, жёсткие ограничения, DE (QUICK)

Оценено 144 варианта, 142 с расчётом, **0 допустимых, 0 строго допустимых**.
Лучший: `l_с1 = 9.35 мм`, `α2 = 79.1 / 82.9 / 86.6°`, но `π₃ = 2.63`, `u_т > 400`, `l_с1 < 14`.
Локальная доводка: `l_с1 = 10.25 мм`, `α2 = 70.0 / 81.9 / 85.5°`, `η*т = 0.9064`, но всё ещё
недопустим по π₃ / u / l_с1.

Это подтверждает предел: при N = 110 кВт `l_с1,max ≈ 9…10 мм` при книжном α2.

### Обратная оптимизация (режим C / `optimize_initial_conditions.py`)

Найдено строго допустимое решение при **N = 450 кВт** (π*к = 11, T*г = 1250 К):

| Параметр | Значение |
|---|---:|
| l_с1 | **20.02 мм** |
| α2 | **72.2 / 88.7 / 84.1°** |
| π ступеней | **2.06 / 2.12 / 2.37** |
| η*т | **0.9120** |
| σ_max | 285 МПа |
| u_т | 375 м/с |
| G_в | 2.41 кг/с |
| γ_max | 16.8° |
| ρ корня | 0.050 / 0.060 / 0.137 |
| λ_c1 | 0.902 / 0.877 / 0.859 |
| длины | 20.0 → 20.5 → 28.1 → 32.4 → 38.3 → 49.7 мм |

Все проверки `validate()` пройдены (см. `results/initial_conditions_checks.csv`).
Режим 2 (`--mode 2`) выбирает N = 480 кВт, `l_с1 = 20.41 мм`, `η*т = 0.9128`.

**Важно:** это уже другой типоразмер (класс TPE331), а не требование N = 110 кВт.
При N = 110 кВт одновременное выполнение α2 ≥ 70° и l_с1 ≥ 20 мм невозможно по неразрывности.

### Можно ли вытянуть l_с1 ≥ 20 мм ухудшением КПД цикла?

`scan_cycle_coefficients.py` (π*к = 11, T*г = 1250 К, N = 110 кВт; η_т = 0.87,
η_м = 0.96, η_р = 0.93, σ_вх = 0.95, σ_г = 0.93, π_с = 1.10 — уже ниже книги):

| η_к | G, кг/с | l_с1, мм | η_e | C_e, кг/(кВт·ч) | строго |
|---:|---:|---:|---:|---:|---|
| 0.85 (низ книги) | 0.841 | 12.39 | 0.1801 | 0.463 | нет |
| 0.81 | 1.036 | 13.59 | 0.1521 | 0.549 | нет |
| 0.77 | 1.416 | 15.53 | 0.1169 | 0.714 | нет |
| 0.73 | 2.460 | 19.32 | 0.0714 | 1.168 | нет |
| 0.71 | 4.206 | 22.52 | 0.0433 | 1.926 | **да** |

Вывод: да, математически l_с1 ≥ 20 мм получается при **η_к ≈ 0.71** и η_e ≈ 4.3 %
(C_e = 1.93 кг/(кВт·ч) против 0.325 в исходном цикле, в 5.9 раза хуже).
Это не «немного отклониться по КПД», а фактически другой, крайне неэкономичный двигатель.
В книжных пределах η_к = 0.85…0.87 длина остаётся ≤ 12.4 мм.
Числа пересчитаны после уточнения `c_т` = 180,1 м/с (`M_т` = 0.3379).
Проверка σ использует допуск 1e-4 — это сходимость итерации `A_т`, а не физическое послабление.

## Аудит послаблений

В оптимизаторе (`optimizer_core.validate`) оставлены только книжные/физические границы:

* α2 1-й и промежуточных ступеней — **70…90°**, последней — **80…90°**;
* α1 средний и у корня — **≥ 11°**;
* σ_р — **≤ σ_л** без запаса 0,5 %;
* длины лопаток — **не убывают** без допуска 0,1 %;
* π 1,8…2,4; u ≤ 400 м/с; l_т/D_т ≤ 1/3; γ ≤ 25°; ρ корня ≥ 0,05; λ_c1 ≤ 1,05.

Переключателей `strict_alpha2`, `20…90` и `+1°` в оптимизаторе больше нет.

В исходном `Main_Turbinis_Calc_Book.ipynb` (я его **не менял**) остались такие же
проектные послабления:

| Место | Послабление |
|---|---|
| `α2_ст1 = (20.0, 90.0)` | α2 1-й ступени 20…90° вместо 70…90° |
| проверка α2 | `+ 1.0°` к верхней границе |
| проверка σ_р | `σ_л * 1.005` (0,5 %) |
| проверка длин | `b >= a * 0.999` (0,1 %) |
| вход `α1_ст` | α1 1-й ступени 9,25° (книга 11…14°) |

Это исходное состояние проекта, а не ограничения оптимизатора. Если их тоже нужно
привести к книге, основной блокнот остановится на текущем варианте
(α2₁ = 21,7°, α1₁ = 9,25°, α2₃ = 90,5°) — что и является корректной диагностикой.

## Ограничения инструмента

* Бюджеты `QUICK` малы; для инженерной доводки увеличивайте `DE_MAXITER`, `DE_POPSIZE`, `LOCAL_STEPS`.
* Полная валидация (ρ корня, λ, γ, решётки) выполняется для финалистов; в DE используется ядро.
* DE стохастична; результаты зависят от `seed`, но проверяются независимо.
* Тёплый старт режима C — инженерная оценка по пределу `l_с1 ~ √N`; финальное решение считается моделью.
* Скрипт обратной оптимизации перебирает 6 точек в `--quick`; полный набор — 60 точек.
